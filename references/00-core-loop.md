# 00 Core Loop

本参考定义会话启动、项目读取、模式路由和阶段停止条件。SKILL.md 只保留路由摘要；执行前按模式加载对应参考。

## 1. 会话启动

1. 判断请求是否在本 skill 范围：
   - 普通文学知识问答、单纯摘要/翻译/错别字校对、与剧本/小说创作或叙事拆解无关的一般写作，默认不触发。
   - 作者明确调用本 skill 时进入；请求意图清楚时可按模式触发条件自动选择。
2. 确定主模式：
   - 请求清楚且无歧义地只匹配一个主模式时，自动选择该模式并直接进入该模式的必要问题；不额外要求模式确认。
   - 仅当请求真正模糊、多模式且无明确顺序，或与当前项目冲突时，才要求作者选择模式。
   - 多模式有明确顺序时提出组合路由并请求确认。
   - 清楚选定模式后的第一个问题：生成模式问首个必要叙事权重问题；辅写模式问辅写目标与范围问题；拆解模式问输出格式问题；具体创作请求缺少理由时问苏格拉底门要求的单个理由问题。
3. 确定项目目录：
   - 已有项目目录时运行 `status` 和 `source status`，读取当前项目、来源、canon 和版本状态。
   - 新任务无项目时询问：复用已有项目、创建新项目，或先只读拆解。
4. 新项目必须由作者确认项目名、`script_master` 和 `interaction_profile` 后再执行 `init`。
5. 按模式加载：
   - 生成：`30-generate.md` + `20-socratic-questioning.md` + `21-confirmation-and-canon.md` + `40-outputs-and-rendering.md`。
   - 辅写：`31-assist.md` + 上述通用参考。
   - 拆解：`32-decompose.md` + `40-outputs-and-rendering.md`。
   - 所有模式共享 `00-core-loop.md`、`10-project-model.md`、`50-quality-and-conflicts.md`、`60-errors-security-and-fallbacks.md`。

## 2. 模式路由规则

- 同一任务同一时间只执行一个主模式。
- 清楚匹配单一模式时自动路由，不把模式确认当作额外 gate。
- 组合路由中的每个模式内部 gate 不能被预授权跳过。
- 前一模式完成后默认暂停；只有作者明确预授权继续时才进入下一模式。
- 模式切换必须写入 `logs/decisions.jsonl`，事件中记录旧模式、新模式、作者声明和生效时间。

## 3. 阶段停止条件

### 生成模式
- 模式未确定（请求模糊或多模式无顺序）：不进入；清楚匹配生成模式时自动选定并直接提问。
- 未读取并登记来源：不进入提问。
- 未确认叙事权重和作品定位：不生成总结。
- 未明确篇幅、核心内容和世界规则初步架构：不得启动正文。
- 总结未确认：不生成大纲。
- 大纲未确认：不生成四类列表。
- 四类列表未确认：不生成正文。
- 每个确认批次完成后更新 canon、决策记录和版本，再继续下一批。

### 辅写模式
- 未确认辅写目标、保留范围和改动边界：不进行只读诊断。
- 未生成并确认变动表：不改写正文。
- 创作性改动未逐项确认：不写入正文。
- 纯文字修复可批量处理，但必须先列出编号、理由、影响和状态。

### 拆解模式
- 未确认图谱、时间线、地图和四类列表版本：不开始只读解析。
- 全程只读；任何建议只输出，不实施。
- 发现 canon 问题时只输出建议，不修改 canon。

## 4. 暂停与续接

- 默认在每个阶段门和每个模式结束后暂停，等待作者明确回复。
- 作者可使用交互配置切换确认粒度或版本节奏，但不能绕过硬性确认门。
- 中断后恢复时，先读 `status`、`logs/decisions.jsonl` 和当前 `working/` 状态，不重复已确认内容。
